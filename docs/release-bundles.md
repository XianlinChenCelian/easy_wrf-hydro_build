## 本地附件目录

发布目录使用 `releases/<系统-架构>/<编译器>/<WRF-Hydro 版本>/`。每个版本对应一个独立附件。`index.json` 记录附件类型、相对路径和可用替代路线。GitHub Releases 附件使用独立文件名，目录和索引随发布清单展示。

```text
releases/
  linux-x86_64/
    gnu/5.4.0/      # GNU 离线包和 SHA256
    intel/5.4.0/    # Intel 源码配方和 SHA256
  linux-aarch64/
    gnu/5.4.0/
    intel/5.4.0/    # 平台限制与替代路线
  osx-arm64/
    gnu/5.4.0/
    intel/5.4.0/    # 平台限制与替代路线
  windows-x86_64/
    gnu/5.4.0/      # 指向 x86_64 Linux 来宾包
    intel/5.4.0/    # 指向 x86_64 Linux 来宾配方
```

`5.1.2`、`5.2.0` 和 `5.4.0` 都使用上述目录结构。现有 GNU 离线包保留原文件名与校验值。x86_64 Linux GNU 三版已在超算的原生计算节点验收。WSL2 与虚拟机使用与来宾架构匹配的 Linux 附件，见 [Linux 安装与验证](linux-validation.md)。Intel 条目的要求与验收状态见 [Intel 编译器矩阵](intel-compiler-matrix.md)。

维护者用 `scripts/release/assemble_release_tree.py` 将已有 GNU 包、模型与算例源包和依赖源包组装到一个新目录。脚本验证 GNU 包的 SHA256，为 Intel 源码配方生成依赖与完整性清单。现有版本附件可继续按原方法使用。

需要 WRF/WPS 的用户可另选与 Hydro 版本对应的源码附加包。每个附加包包含相应的 WRF/WPS、GRIB2 依赖和编译入口，安装时复用所选 GNU 或 Intel 环境。版本搭配、主机要求和构建说明见 [WRF/WPS 扩展](wrf-wps.md)。

完整发布目录可通过 `--atmosphere-archives /path/to/wrf-wps-sources` 加入这些附加包。索引会把适用的系统和编译器条目指向同一份对应版本源码。

## 从 GitHub 源码制作单个 Intel 配方

先按[源码归档清单](source-archives.md)准备四个依赖源包。再下载所选版本的模型源包及对应 Croton 算例，文件名见[版本安装说明](versioned-install.md)。在仓库根目录执行：

```bash
python3 scripts/release/assemble_release_tree.py \
  --intel-version 5.4.0 \
  --model-archives /path/to/model-and-croton \
  --dependency-archives /path/to/dependency-sources \
  --output /path/to/releases
```

将 `5.4.0` 改为 `5.1.2` 或 `5.2.0` 即可生成该版本的 `linux-x86_64/intel/版本/` 附件。超算选择已加载的站点工具链，个人电脑按配方里的 `ONEAPI.md` 安装官方 Intel 工具链。Windows 用户在 WSL2 或 Linux 虚拟机内执行。见 [Intel 编译器矩阵](intel-compiler-matrix.md)。

## GNU 离线包内容

- 选定版本的 WRF-Hydro 原始源码及匹配的 Croton 算例。
- 已验证环境中的全部 conda 软件包，包括 GNU Fortran、MPI、NetCDF-C、NetCDF-Fortran、HDF5、压缩库、CMake 和传递依赖。
- 每个软件包的精确版本、构建号、来源、许可证标识和 SHA256。
- 独立环境安装器 micromamba、项目 Python 源码、安装入口和文件校验清单。

安装从包内文件恢复依赖，无需联网求解或手动选择 NetCDF 版本。主机仍需 Python 3.9+ 与 Apple Command Line Tools 提供的系统 SDK、C 编译器、make，以及系统 Bash/csh；这些主机组件没有打入离线包。

不同模型版本可以共用经验证的依赖版本，但各自保留独立清单及验收记录。现有 Mac 原生实跑采用 GNU Fortran 15.3.0、OpenMPI 5.0.11、NetCDF-C 4.10.1、NetCDF-Fortran 4.6.4。5.1.2 的编译兼容设置和 5.4.0 的 CMake 路径由安装工具按模型版本处理。参见[已验证构建](verified-builds.md)。

## 安装

先运行 `python3 install.py /absolute/path/to/new-install --check-only` 检查系统和目录。安装失败或中断后，用相同包和目录加 `--resume` 继续。权限、共享盘、WSL、空间不足和 MPI 失败的处理见[安装恢复指南](installation-recovery.md)，每包也附带 `TROUBLESHOOTING.md`。

解压所选附件，进入其目录，执行以下命令，安装目标必须为新目录。

```bash
python3 install.py /absolute/path/to/new-install --run-example --jobs 4
```

包可以存放在移动硬盘，Mac 构建目录建议使用 APFS。`--dry-run` 会实际恢复隔离依赖环境，但只生成模型编译脚本。生成的 `manifest.json` 记录精确依赖，包外 `.sha256` 用于校验下载，包内 `checksums.json` 在安装时自动检查。

## 维护者生成候选包

```bash
python3 scripts/release/build_offline_bundle.py \
  --version 5.4.0 \
  --environment /path/to/validated/environment \
  --cache /path/to/mamba/pkgs \
  --archives /path/to/model-and-croton-archives \
  --micromamba /path/to/micromamba \
  --output /path/to/release-candidates
```

一次命令只生成一个版本。构建器校验缓存包 SHA256 与已安装环境记录一致，接受 `osx-arm64`、`linux-aarch64`、`linux-64` 单一平台环境；生成候选包本身不代表对应平台已经通过测试。Linux `linux-64` 附件命名为 `linux-x86_64`。包内依赖保留原始分发包及其许可证文件。公开发布前需补齐安装器及全部第三方软件的再分发许可证审查、干净主机恢复测试和平台验收；本地成功不等同于所有 Mac 机型已验证。

Linux 平台应单独建立并锁定编译器、MPI 与 NetCDF 环境，然后在原生 Linux、WSL2 和目标虚拟机中验证。只有通过对应验收的附件才标为正式支持。
